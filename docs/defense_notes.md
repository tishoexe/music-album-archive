# Бележки за защита — Music Album Archive

---

## Кратко описание на проекта (за открито представяне)

> „Проектът Music Album Archive е настолно Python приложение за организиране на музикални албуми, песни и изпълнители. Използва локална MongoDB база данни с три колекции — artists, albums и songs — свързани помежду си чрез ObjectId references. Графичният интерфейс е реализиран с Tkinter и предоставя пълен CRUD, търсене с филтри и статистически справки чрез MongoDB Aggregation Pipeline."

---

## Стъпки за демонстрация при защита

### 1. Стартиране
- Покажи терминала: `python app.py`
- Приложението се отваря — покажи header-а, четирите таба, светлия дизайн

### 2. Artists таб
- Покажи таблицата с 5 изпълнителя
- Демонстрирай филтър по Country — напиши "United" → остават само Billie Eilish и Teddy Swims
- Натисни Clear → всички се върнат
- Кликни „+ Add Artist" → попълни нов изпълнител → Save → вижда се в таблицата
- Избери го и кликни „Delete Selected" → покажи confirm диалога → изтрий го

### 3. Albums таб — Reference и $lookup
- Покажи колоната „Artist" — тя **не е записана** директно в albums колекцията
- Обясни: *„В MongoDB albums документите съдържат само artist_id (ObjectId). Когато зарежда таблицата, приложението използва $lookup за да вземе artist name от колекцията artists."*
- Кликни „+ Add Album" → покажи dropdown-а с имена на изпълнители → обясни че при Save се записва ObjectId, не text

### 4. Songs таб — двоен $lookup
- Покажи колоните: Title, Album, Artist — и трите идват от различни колекции
- Обясни: *„Песните съдържат album_id и artist_id. При зареждане се правят два $lookup — един към albums, един към artists — за да се покажат заглавие на албума и ime на изпълнителя."*
- Покажи филтъра по Artist — напиши "Billie" → остават само нейните песни

### 5. Statistics таб
- Кликни „Albums per Artist" → таблица с брой албуми на изпълнител
- Кликни „Songs per Artist" → таблица с брой песни
- Покажи реда „Average songs per album" в горната част
- Обясни: *„Тези справки използват $group за групиране и $lookup за добавяне на имената."*

### 6. MongoDB Compass (отвори паралелно)
- Отвори колекция `albums` → покажи поле `artist_id: ObjectId(...)`
- Обясни разликата с релационна база: *„Вместо foreign key constraint, MongoDB използва ObjectId references — ние сами ги управляваме в кода."*
- Отвори колекция `songs` → покажи `album_id` и `artist_id` като ObjectId

## Очаквани въпроси и отговори

**В: Защо не embedded documents вместо references?**  
О: При embedded трябва да дублираме данните за изпълнителя в всеки албум. Ако сменим нещо, трябва да го обновим на много места. С references го пазим само на едно — в artists колекцията.

**В: Какво е $lookup?**  
О: $lookup е stage в MongoDB Aggregation Pipeline, аналог на SQL JOIN. Взима документи от друга колекция и ги прикачва към текущите резултати по зададено поле.

**В: Как работи $regex?**  
О: $regex позволява текстово търсене с регулярен израз. Опцията `"i"` го прави case-insensitive — т.е. "billie" ще намери "Billie Eilish".

**В: Защо artist_id е в songs, ако вече го има в albums?**  
О: За по-ефективни заявки. Ако искаме всички песни на даден изпълнител, можем да търсим директно в songs по artist_id — без да минаваме през albums.

**В: Какво е ObjectId?**  
О: ObjectId е специален тип в MongoDB — 12-байтов уникален идентификатор, автоматично генериран от базата данни. Използва се за _id на документите и за references между колекции.

## MongoDB операции в проекта

| Операция | Където се използва |
|----------|--------------------|
| `insert_one` | Add Artist / Album / Song |
| `find` с `$regex` | Филтри в Artists таб |
| `update_one` | Edit Artist / Album / Song |
| `delete_one` | Delete Artist / Album / Song |
| `count_documents` | Проверка преди изтриване |
| `$lookup` | Albums таб, Songs таб, Statistics |
| `$unwind` | Разгъване на lookup резултати |
| `$match` | Филтриране след lookup |
| `$group` | Statistics — брой по групи |
| `$sort` | Сортиране на резултати |
| `$project` | Избор на полета в изхода |
| `$avg` | Средно число песни на албум |
